# 桌游回合规则验证器

用表单定义**有限状态变量**、**初始值**和一组带**条件 + 赋值**的规则；系统从初始状态出发做
**广度优先（BFS）状态空间探索**，自动找出两类危险状态并给出**最短触发路径**：

- **死锁（deadlock）**：当前状态下没有任何规则的条件成立；
- **互斥冲突（conflict）**：同一个互斥组里有多条规则同时可执行（玩家不知道该触发哪一条）；
- 另附 **越界赋值（invalidAssignment）**：规则赋值结果超出变量域（如整数越界、赋了不存在的枚举值）。

探索对状态**去重**；当因达到状态上限或步数上限而无法覆盖全部可达状态时，结果明确标记为
**「不完备」**，此时 `safe` 恒为 `null`，**绝不会误报安全**。

```bash
docker compose up --build
```

然后用浏览器打开：

docker compose down

## 使用说明

### 1. 定义状态变量

每个变量要么是**整数区间**（`min` ~ `max`，初始值必须在区间内），要么是**枚举**
（显式列出所有允许的值，数字或字符串均可）。变量名支持中文，例如 `能量`、`阶段`。

### 2. 定义规则

一条规则包含：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 规则名 | 路径中展示的名称 | `攻击` |
| 触发条件 | 安全表达式引擎，**不使用 eval** | `阶段=="行动" && 能量>=2` |
| 互斥组 | 可空；同组内多条规则同时成立即报冲突 | `行动` |
| 赋值 | 一条或多条，**并行赋值**（右式全部基于赋值前状态） | `能量 → 能量-2` |

表达式支持：数字 / 字符串 / 布尔字面量、变量引用（含中文）、`+ - * / %`、
`> >= < <= == !=`、`&& ||`、`!`、括号。字符串用单/双引号。

> 并行赋值意味着可以直接交换两个变量：`a → b`、`b → a` 同时执行。

互斥语义：**未分组的规则默认不参与冲突检测**（它们通常是“系统流转”规则）。
勾选「所有规则默认互斥」后，未分组规则会被归入同一个默认互斥组。

### 3. 设置探索边界

- **最大步数**：BFS 的深度上限；
- **状态上限**：最多访问的不同状态数，防止状态空间爆炸；
- 任一边界被触发，结果页都会显示黄色「结果不完备」横幅。

### 4. 阅读结果

- 结果横幅三态：**✓ 验证通过（完备）** / **✗ 发现问题（完备）** / **⚠ 结果不完备**；
- 每个问题给出问题状态、深度与**最短触发路径**（初始 → 规则 A → 规则 B …），
  可展开查看路径上每一步的完整状态；
- 问题按最短路径排序，方便定位最容易触发的情况。

## 规则集 JSON 导入 / 导出

- 点击 **「⇩ 导出规则集 JSON」** 下载当前表单为 JSON 文件；
- 点击 **「⇧ 从文件导入」** 选择 JSON 文件，或 **「从文本导入」** 直接粘贴；
- 导出格式（`ruleset.json`）：

```json
{
  "format": "turn-rule-validator/1",
  "variables": [
    { "name": "能量", "kind": "range", "min": 0, "max": 10, "initial": 0 },
    { "name": "阶段", "kind": "enum", "values": ["抽牌", "行动", "结束"], "initial": "抽牌" }
  ],
  "rules": [
    {
      "name": "攻击",
      "condition": "阶段==\"行动\" && 能量>=2",
      "group": "行动",
      "actions": [
        { "target": "能量", "expr": "能量-2" },
        { "target": "阶段", "expr": "\"结束\"" }
      ]
    }
  ],
  "options": { "maxSteps": 15, "stateLimit": 10000, "defaultMutex": false }
}
```

导入时也兼容 `actions` 写成 `assignments: { "变量": "表达式" }` 的简写形式。
页面内置「载入示例」，其中同时包含互斥冲突、越界赋值与死锁样例。

## HTTP API

`POST /api/analyze`，请求体即规则集 + 探索参数；返回结果中：

```json
{
  "ok": true,
  "result": {
    "safe": false,              // true=安全；false=有问题；null=探索不完备，不能判定
    "complete": true,           // 状态空间是否完整展开
    "truncatedStateLimit": false,
    "truncatedDepth": false,
    "counts": { "statesVisited": 95, "transitions": 149, "deadlock": 6, "conflict": 21, "...": "..." },
    "findings": [
      {
        "type": "conflict",
        "depth": 1,
        "state": { "阶段": "行动", "能量": 3, "...": "..." },
        "group": "行动",
        "conflictingRules": ["攻击", "防御", "蓄力"],
        "path": { "length": 1, "rulePath": ["开始行动"], "transitions": [ "..."] }
      }
    ]
  }
}
```

模型或表达式校验失败时返回 HTTP 400 与中文错误信息。

## 项目结构

```
server.js              Express 入口（静态页 + /api/analyze）
src/expr.js            安全表达式引擎：词法/语法分析 + 求值（无 eval）
src/model.js           变量与规则的校验、归一化与编译
src/explorer.js        BFS 探索器：去重、死锁/冲突/越界检测、完备性判定
public/                原生前端（HTML + CSS + JS，无框架、无构建）
test/                  node --test 单元测试（20 个用例）
Dockerfile, docker-compose.yml
```

## 设计要点

- **BFS + 去重**：每个状态只在其最短深度被访问一次，父边记录用于重建最短触发路径；
- **完备性优先于安全结论**：状态上限或步数上限触及时 `complete=false`、`safe=null`，
  前端只在“完备且零发现”时显示安全；
- **状态有界**：变量域有界、状态数与规则数有硬上限、发现数量截断（保留路径最短的 200 条）；
- **安全求值**：规则表达式经显式词法/语法解析，变量引用必须事先声明，杜绝任意代码执行。
